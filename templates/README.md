# Шаблоны работ

Наборы задач, выведенные из истории этого же трекера: `TASQDEV` (разработка `tasq`) и `RRL`
(каталог, Kerberos, совместимость с чужими клиентами). Каждый — то, чем работа на самом деле
оказывалась: не пожелание, а сумма шагов, которые в этих эпиках уже были пройдены.

Файл содержит ровно то, что принимает `tasq template save --file`: `{"nodes": [...]}`. Имя шаблона
берётся из имени файла, переменные — из `{скобок}` в заголовках, их печатает `tasq template ls`.
`kind` намеренно не указан ни в одном узле: вид выводится из глубины при применении (эпик —
глубина 1, задача — 2, подзадача — 3), поэтому один и тот же шаблон применим и в корень проекта, и
под задачу. Указать `kind` всё же можно — это подсказка о замысле: место в дереве всё равно решает,
а расхождение называется числом («N declared kind(s) follow the depth instead»). Объявления внутри
шаблона при этом обязаны быть согласованы между собой: «корень-задача с ребёнком-эпиком» —
противоречие, и оно ловится при сохранении, а не при применении.

## Загрузить

```bash
make templates TEMPLATES_DB=~/.local/share/tasq/hermes.db
```

Без `TEMPLATES_PROJECT` шаблоны грузятся ОБЩИМИ — доступными во всех проектах базы. Так и задумано:
каталог описывает, как ведётся работа, а ведётся она одинаково везде. Названный проект — когда
каталог нужен одному проекту:

```bash
make templates TEMPLATES_DB=… TEMPLATES_PROJECT=TASQDEV
```

Или по одному:

```bash
tasq template save protocol-defect --file templates/protocol-defect.json --global
tasq template apply protocol-defect --var symptom="TGS без FAST" --parent RRL-2
```

`tasq template ls` без `--project` показывает всё в базе и называет владельца каждого шаблона
(`(global)` — общий). В проекте видно свои и общие; проект вправе переопределить общий одноимённым,
и переопределение побеждает — так общий шаблон можно поправить под проект, не переименовывая.
Удалить общий из проекта нельзя (`GLOBAL_TEMPLATE`): он принадлежит всей базе, а не проекту.

Применение без обязательной переменной — отказ, а не `{symptom}` в заголовке задачи.

## Почему именно эти, а не «типовые»

Шаблон — это запись процесса, а не список пожеланий. Поэтому в каждом есть шаг, который в этих же
эпиках оказывался решающим и который легко пропустить: в `measure-gate` — числа до правки, в
`schema-migration` — откат на копии, в `protocol-defect` — приёмка живым клиентом, в
`perf-regression` — гипотеза до правки (в TASQDEV-12.3 гипотеза «дорого читать строки» оказалась
неверной: 38 из 41 мс уходило на материализацию представления).

## Гейт

`tests/templates.rs` загружает каждый файл каталога в чистую базу, применяет его в корень и под
узел и сверяет число созданных узлов с ожидаемым. Новый файл без строки в таблице выше или с
шаблоном вроде `{забытая}` — роняет прогон.
