# TUI: что делает, чего не делает и почему так устроен

Статус: спека (TASQDEV-6.1). Основание для задач 6.3–6.12. Замер стоимости — в разделе
«Упаковка» (TASQDEV-6.2), он же фиксирует принятое решение цифрами.

## Для кого

Для человека. Агенты работают через MCP и в терминал не смотрят: интерактивный экран нужен там,
где нужно окинуть взглядом состояние и поправить его одной клавишей — доска, аренда, статус,
заметка. Это не второй интерфейс к базе, а второй способ смотреть на те же сущности.

## Границы

- **Данные — из библиотеки, не из вывода CLI и не из SQL.** Колонки доски берутся из
  `overview::board`, переходы — из `status`, аренды — из `lease`. Причина простая: правила
  (матрица статусов, истечение аренды, журнал) живут в одном месте, и второй их экземпляр в TUI
  разошёлся бы с первым на первой правке — ровно так уже было с фильтром в слое вывода,
  где `--json` и таблица показывали разные списки.
- **Чтение не требует аренды; запись — только явным действием.** Просмотр доски, карточки,
  заметок не берёт и не продлевает аренду. Взятие аренды, переход статуса, правка узла и
  добавление заметки — отдельные действия, каждое в своей транзакции, каждое пишется в журнал
  так же, как из CLI.
- **Один кадр = одно чтение.** Данные читаются перед отрисовкой, а не во время: экран не
  держит соединение открытым на запись, и ошибка чтения показывается в строке состояния, а не
  выходит из цикла.
- **Ничего в обход fail-fast.** Недопустимый переход не «подкручивается»: TUI показывает отказ
  `INVALID_TRANSITION` и подсказку, какие переходы допустимы. Guarded переходы (закрыть узел с
  открытыми детьми, переоткрыть закрытый) требуют подтверждения — это аналог `--force`, но
  решение принимает человек, а не флаг в скрипте.

## Экраны

1. **Доска** — колонки по эффективному статусу, счётчики, строки: dot-ID, приоритет,
   прогресс, держатель аренды, срок, название. Просроченные помечены, узлы в аренде помечены.
2. **Карточка узла** — описание, цепочка `ctx` от корневого эпика, дети, зависимости
   (`dep graph`), история статусов, заметки и комментарии. Редактирование описания — внешним
   редактором по `$EDITOR`, а не встроенным полем: встроенное поле на десять строк не заменяет
   редактор, а имитирует его.
3. **Форма узла** — создание и правка полей по одному, `Tab` между полями, `Esc` отбрасывает
   без записи. Поля: название, описание, приоритет, срок, оценка, вес.
4. **Поиск** — полнотекстовый (`overview::search_all`), переход к найденному узлу.
5. **Строка состояния** — проект, счётчики, сообщение об отказе последнего действия.

## Карта клавиш (первая версия)

| клавиша | действие |
|---|---|
| `j` / `k`, `↓` / `↑` | движение по строкам |
| `h` / `l` | смена колонки на доске |
| `Tab` | следующее поле в форме |
| `Enter` | карточка узла / подтвердить действие |
| `Esc` | отменить форму или подтверждение, вернуться на доску |
| `c` | взять аренду (claim) |
| `r` | отпустить аренду (completed / released / failed — выбор в подтверждении) |
| `s` | сменить статус (список допустимых переходов, а не свободный ввод) |
| `a` | создать узел в выбранной колонке |
| `e` | править выбранный узел |
| `n` | заметка к узлу |
| `m` | комментарий к узлу |
| `/` | поиск |
| `?` | справка по клавишам |
| `q` | выход (с подтверждением, если есть несохранённая форма) |

Клавиши — данные, а не код: таблица «клавиша → намерение» проверяется тестом целиком, потому
что забытая строка — это молча неработающая клавиша.

## Чего в первой версии нет

- **Мыши.** Отдельный слой разбора координат, и он не нужен, пока клавиатура покрывает всё:
  мышь добавляется, когда найдётся действие, которое без неё неудобно.
- **Нескольких окон и вкладок.** Один экран, один стек: доска → карточка → форма. Вкладки
  вводят состояние, которое надо синхронизировать, а выгода нулевая.
- **Правки схемы и проектов.** Создание проекта, миграции, экспорт — операции, которые
  делаются один раз и требуют чтения вывода. Им место в CLI.
- **Цветов как смысла.** Цвет — подсказка, а не носитель информации: при `--once`, в логе и на
  монохромном терминале смысл остаётся читаемым.

## Упаковка: тот же бинарь

Замер (TASQDEV-6.2), сборка `release` в образе `rust:1.99.1-bullseye`, каталог сборки удалён
перед каждым прогоном, два прогона в разном порядке:

| | без ratatui | с ratatui 0.30 (features `crossterm`, `std`) |
|---|---|---|
| размер бинаря | 14 610 168 Б | 15 106 472 Б |
| прирост | — | **+496 304 Б (≈ 0,47 МиБ, +3,4 %)** |
| максимальная GLIBC | 2.30 | **2.30** |
| сборка с нуля | 84 с, 96 с | 70 с, 71 с |
| новых пакетов в lock | — | 55 |
| `cargo deny check` | — | проходит (то же предупреждение о двух `syn`) |

Решение: **TUI — подкоманда `tasq tui` в том же бинаре.** Причины:

- порог отказа был 2 МиБ прироста и GLIBC выше 2.30; фактические 0,47 МиБ и 2.30 остаются
  внутри контракта артефакта (Astra/Debian 11 несут 2.31);
- время сборки не выросло: 84/96 с без библиотеки против 70/71 с ней. Прирост в 55 пакетов не
  удлинил критический путь — он определяется `rusqlite` (C-сборка SQLite) и `tiktoken-rs`, а
  мелкие крейты компилируются параллельно с ними. Обратный порядок прогонов даёт те же числа,
  поэтому это не эффект прогретого кэша;
- второй бинарь означал бы второй артефакт, вторую проверку glibc и вторую строку в `release.yml`
  ради 0,47 МиБ.

Отдельная cargo-фича (`--features tui`) остаётся возможной, если когда-нибудь понадобится
сборка без TUI, но по умолчанию она не нужна: артефакт один.

## Проверка

- **`tasq tui --once`** печатает ровно один кадр в обычный вывод и выходит. Это единственный
  способ проверить TUI в CI, где нет терминала, и он же снимает картинку для документации.
  Проверено на копии живой базы: кадр содержит строку состояния и таблицу, узлы в аренде
  подписаны держателем.
- **Решения — чистыми функциями.** `решение(состояние, событие) -> Решение` не знает про
  терминал, поэтому клавиши, границы списка, отбрасывание черновика и подтверждения
  проверяются тестами без псевдотерминала. Кадр проверяется по буферу `TestBackend` — на то,
  что строка вкладок и шапка вообще на экране; раскладку смотреть глазами, а не ассертами на
  координаты.
- **Отпускание и автоповтор клавиши нажатием не считаются** (`KeyEventKind`): иначе удержание
  `j` уезжает на десяток строк и читается как «дёрганый скролл».
