# TUI: что делает, чего не делает и почему так устроен

Статус: спека (TASQDEV-6.1). Основание для задач 6.3–6.12. Замер стоимости — в разделе
«Упаковка» (TASQDEV-6.2), он же фиксирует принятое решение цифрами.

## Для кого

Для человека. Агенты работают через MCP и в терминал не смотрят: интерактивный экран нужен там,
где нужно окинуть взглядом состояние и поправить его одной клавишей — доска, аренда, статус,
заметка. Это не второй интерфейс к базе, а второй способ смотреть на те же сущности.

## Границы

- **Данные — из библиотеки, не из вывода CLI и не из SQL.** Колонки доски берутся из
  `overview::board`, переходы — из `status`, аренды — из `lease`. Причина простая: правила
  (матрица статусов, истечение аренды, журнал) живут в одном месте, и второй их экземпляр в TUI
  разошёлся бы с первым на первой правке — ровно так уже было с фильтром в слое вывода,
  где `--json` и таблица показывали разные списки.
- **Чтение не требует аренды; запись — только явным действием.** Просмотр доски, карточки,
  заметок не берёт и не продлевает аренду. Взятие аренды, переход статуса, правка узла и
  добавление заметки — отдельные действия, каждое в своей транзакции, каждое пишется в журнал
  так же, как из CLI.
- **Один кадр = одно чтение.** Данные читаются перед отрисовкой, а не во время: экран не
  держит соединение открытым на запись, и ошибка чтения показывается в строке состояния, а не
  выходит из цикла.
- **Ничего в обход fail-fast.** Недопустимый переход не «подкручивается»: TUI показывает отказ
  `INVALID_TRANSITION` и подсказку, какие переходы допустимы. Guarded переходы (закрыть узел с
  открытыми детьми, переоткрыть закрытый) требуют подтверждения — это аналог `--force`, но
  решение принимает человек, а не флаг в скрипте.

## Экраны

0. **Панель проектов** — все проекты базы слева: ключ и число узлов, текущий подсвечен. `Tab`
   переводит фокус на панель и обратно, `j`/`k` листают проекты, `Enter` переключает доску.
   `--project` не обязателен: он задаёт только проект, с которого экран открывается.
1. **Доска** — колонки по эффективному статусу, счётчики, строки: dot-ID, приоритет,
   прогресс, держатель аренды, срок, название. В шапке — счётчики доски; проект выбирается
   панелью слева, второй переключатель не нужен и не рисуется. Два вида одной доски: `список` (таблица) и `канбан` (колонки статусов рядом,
   адрес и название двумя строками); `v` переключает, данные при этом не перечитываются. Просроченные помечены, узлы в аренде помечены.
   Оба вида прокручиваются: курсор держится последней видимой строкой, а когда возвращается к
   началу, окно возвращается вместе с ним. До этого таблица рисовала все строки, и на доске
   длиннее экрана клавиши двигали курсор за нижний край — видно было только начало.
   Внизу канбана — панель текста выбранной задачи (20 % высоты): адрес, приоритет, прогресс,
   название и описание из базы. В колонке шириной в десять знаков от названия остаётся
   «TUI: инт…», поэтому без панели канбан показывает адреса, а не работу.
2. **Карточка узла** — заголовок, статус, приоритет, прогресс, срок, держатель и подсказка о
   действиях. Справа у списка постоянная боковая панель: цепочка `ctx` от корневого эпика,
   последние заметки проекта и последние комментарии узла — три раздела, а не один список,
   потому что это разные вопросы («где я в дереве», «что решено», «что сказали»).
   Правка описания — формой (поле «описание»), а не внешним редактором: запускать `$EDITOR`
   поверх альтернативного экрана значит отдавать терминал чужому процессу и разбираться с его
   состоянием после возврата.
3. **Форма узла** — создание и правка. Поля показываются ВСЕ сразу (иначе исправление опечатки в
   третьем поле требует помнить первые два), ввод идёт в текущее, `Tab`/`Shift-Tab` — по кругу,
   `Enter` — запись, `Esc` — отмена без записи. Поля: название, описание, приоритет, срок.
   Правка читает значения из БАЗЫ, а не из доски: описания на доске нет вовсе, и форма,
   заполненная по ней, потеряла бы его при сохранении. Валидация — библиотечная
   (`node::create`, `node::update`), поэтому пустое название, приоритет вне списка и срок не
   датой отбиваются с названным полем.
4. **Поиск** — полнотекстовый (`overview::search_all`), переход к найденному узлу.
5. **Строка состояния** — проект, счётчики, сообщение об отказе последнего действия.

## Карта клавиш (первая версия)

| клавиша | действие |
|---|---|
| `j` / `k`, `↓` / `↑` | движение по строкам (в поиске — по результатам) |
| `h` / `l` | смена колонки на доске |
| `Tab` | следующее поле в форме |
| `Enter` | карточка узла / подтвердить действие |
| `Esc` | отменить форму или подтверждение, вернуться на доску |
| `c` | взять аренду (claim) |
| `r` | отпустить аренду (completed / released / failed — выбор в подтверждении) |
| `s` | сменить статус (список допустимых переходов, а не свободный ввод) |
| `a` | создать узел в выбранной колонке |
| `e` | править выбранный узел |
| `n` | заметка к узлу (одна строка текста) |
| `m` | комментарий к узлу |
| `/` | поиск по всей базе; `Enter` открывает найденный узел, переключая проект |
| `?` | справка по клавишам |
| `v` | вид доски: список ↔ канбан |
| `Tab` | фокус на панель проектов и обратно |
| `j` / `k` на панели | листать проекты |
| `Enter` на панели | переключить доску на выбранный проект |
| `q` | выход (с подтверждением, если есть несохранённая форма) |

Клавиши — данные, а не код: таблица «клавиша → намерение» проверяется тестом целиком, потому
что забытая строка — это молча неработающая клавиша.

## Мышь

Мышь не заменяет клавиатуру, а убирает три действия, где её не хватает: попасть в нужную строку
глазами, листать длинный список и переключить проект.

| действие | что делает |
| --- | --- |
| клик по строке доски или карточке канбана | ставит курсор на этот узел и забирает фокус у панели проектов |
| клик по пустому месту колонки канбана | ставит курсор на колонку |
| клик по проекту в панели слева | переключает доску на этот проект (то же, что `Enter` на панели) |
| клик по панели текста под канбаном | открывает карточку узла |
| колесо | двигает то же, что `j`/`k`; на панели проектов — то же, что её `j`/`k` |

Колесо НЕ прокручивает окно отдельно от курсора: в этой модели прокрутка привязана к курсору, и
второе смещение означало бы два разных ответа на вопрос «где я» — «на пятой строке», а видно
третью.

Координаты переводит в индексы сама отрисовка: она одна знает, сколько строк влезло и с каким
смещением, поэтому карта «прямоугольник → что за ним» собирается за кадр и обнуляется на
следующем. Второй расчёт из модели неизбежно разошёлся бы с первым, и выглядел бы он как «кликнул
по строке, открылся сосед».

## Аварийный выход

Терминал приводится в порядок одним путём на все случаи: сторож снимает захват мыши и выходит из
чужого экрана и при обычном выходе, и при ошибке отрисовки, и при панике в библиотеке. Отдельный
обработчик паники нужен для сборки без размотки стека (`panic = abort`), где `Drop` не
вызывается; он восстанавливает терминал ДО печати сообщения — иначе текст паники приехал бы в
чужой буфер и исчез вместе с ним.

`SIGTERM`, `SIGINT` и `SIGHUP` (закрытый терминал, `kill`, остановка службы) ставят флаг, цикл
видит его на следующем тике и выходит штатно. В самом обработчике сигнала только установка флага:
печатать escape-последовательности оттуда нельзя — обработчик обязан быть async-signal-safe.

Порядок восстановления важен: мышь выключается ПЕРВОЙ. Если выйти из чужого экрана, оставив
захват, оболочка начнёт получать вместо выделения текста последовательности `ESC[<0;…M`.

## Чего в первой версии нет

- **Правки мышью.** Клик и колесо есть (см. ниже), но перетаскивания карточек между колонками
  нет: перенос узла — это смена статуса, у неё есть матрица допустимых переходов и отказ
  `INVALID_TRANSITION`, и превращать её в жест значило бы показывать отказ молчанием.
- **Нескольких окон и вкладок.** Один экран, один стек: доска → карточка → форма. Вкладки
  вводят состояние, которое надо синхронизировать, а выгода нулевая.
- **Правки схемы и проектов.** Создание проекта, миграции, экспорт — операции, которые
  делаются один раз и требуют чтения вывода. Им место в CLI.
- **Цветов как смысла.** Цвет — подсказка, а не носитель информации: при `--once`, в логе и на
  монохромном терминале смысл остаётся читаемым.

## Упаковка: тот же бинарь

Замер (TASQDEV-6.2), сборка `release` в образе `rust:1.99.1-bullseye`, каталог сборки удалён
перед каждым прогоном, два прогона в разном порядке:

| | без ratatui | с ratatui 0.30 (features `crossterm`, `std`) |
|---|---|---|
| размер бинаря | 14 610 168 Б | 15 106 472 Б |
| прирост | — | **+496 304 Б (≈ 0,47 МиБ, +3,4 %)** |
| максимальная GLIBC | 2.30 | **2.30** |
| сборка с нуля | 84 с, 96 с | 70 с, 71 с |
| новых пакетов в lock | — | 55 |
| `cargo deny check` | — | проходит (то же предупреждение о двух `syn`) |

Решение: **TUI — подкоманда `tasq tui` в том же бинаре.** Причины:

- порог отказа был 2 МиБ прироста и GLIBC выше 2.30; фактические 0,47 МиБ и 2.30 остаются
  внутри контракта артефакта (Astra/Debian 11 несут 2.31);
- время сборки не выросло: 84/96 с без библиотеки против 70/71 с ней. Прирост в 55 пакетов не
  удлинил критический путь — он определяется `rusqlite` (C-сборка SQLite) и `tiktoken-rs`, а
  мелкие крейты компилируются параллельно с ними. Обратный порядок прогонов даёт те же числа,
  поэтому это не эффект прогретого кэша;
- второй бинарь означал бы второй артефакт, вторую проверку glibc и вторую строку в `release.yml`
  ради 0,47 МиБ.

Отдельная cargo-фича (`--features tui`) остаётся возможной, если когда-нибудь понадобится
сборка без TUI, но по умолчанию она не нужна: артефакт один.

## Цветовые темы

Набор и значения — как у bottom: шесть встроенных тем `default`, `default-light`, `gruvbox`,
`gruvbox-light`, `nord`, `nord-light`. Выбор — флагом `--theme NAME` (или переменной
`TASQ_THEME`), переключение по кругу — клавишей `T` прямо в TUI. Неизвестное имя — отказ с
перечислением допустимых, а не тихий переход на умолчание.

Что тема задаёт: обычный и приглушённый текст, рамку неактивной панели и акцент панели в фокусе,
шапку таблицы, цвета выделенной строки, фон (от него считается зебра строк сдвигом яркости на
5 %), а также смысловые акценты — статус узла, просрочка, живая аренда, отказ и подтверждение.

Три правила, по которым темы устроены:

- **Имена и значения не выдуманы.** Человек, у которого bottom уже настроен на `nord`, ждёт тот
  же оттенок, а не «похожий».
- **Цвет — подсказка, а не носитель смысла.** Статус написан словом, просрочка — словом и числом
  дней, отказ — кодом. Поэтому кадр читается и без цвета: в `--once`, в логе и на монохромном
  терминале. `--once` печатает кадр БЕЗ цвета намеренно — иначе его нельзя сравнить в гейте.
- **Зебра считается от фона темы.** Литерал сделал бы полосы тёмными на светлой теме; сдвиг
  яркости на 5 % держит их в тон основе.

Файл `src/tui/theme.rs` написан как кандидат в отдельный крейт: зависит только от
`ratatui::style`, ничего не знает про tasq и не трогает ни базу, ни состояние экрана. Пока он
модуль — потому что второй потребитель (`bazis-wp-cli`) живёт в другом репозитории, и подключать
его к нашему крейту без слова владельца нельзя.

## Проверка

- **`tasq tui --once`** печатает ровно один кадр в обычный вывод и выходит. Это единственный
  способ проверить TUI в CI, где нет терминала, и он же снимает картинку для документации.
  Ширина берётся у терминала, если вывод идёт в него; иначе — из `COLUMNS`; иначе 140 знаков, но
  не уже 60 (панель проектов и доска вместе в меньшее не влезают). Цвет — по флагу `--color`:
  по умолчанию кадр печатается без escape-последовательностей, потому что его сравнивают в гейте
  строками, а цветной кадр сравнивал бы сериализатор, а не экран.
  Проверено на копии живой базы: кадр содержит строку состояния и таблицу, узлы в аренде
  подписаны держателем.
- **Решения — чистыми функциями.** `решение(состояние, событие) -> Решение` не знает про
  терминал, поэтому клавиши, границы списка, отбрасывание черновика и подтверждения
  проверяются тестами без псевдотерминала. Кадр проверяется по буферу `TestBackend` — на то,
  что строка вкладок и шапка вообще на экране; раскладку смотреть глазами, а не ассертами на
  координаты.
- **Отпускание и автоповтор клавиши нажатием не считаются** (`KeyEventKind`): иначе удержание
  `j` уезжает на десяток строк и читается как «дёрганый скролл».
